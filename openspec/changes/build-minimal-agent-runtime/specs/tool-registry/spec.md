## Purpose

定义工具的声明、注册、查找与调用契约，使语言模型能够基于工具自描述的参数 Schema 自主决策调用哪个工具以及如何传参。

## ADDED Requirements

### Requirement: 工具声明包含名称、描述与参数 Schema

每个工具 SHALL 声明三项元数据：唯一名称、面向模型的自然语言描述、参数 JSON Schema（含参数名、类型、是否必填与说明）。这三项 SHALL 以模型可直接消费的形式随每次决策请求提交。

#### Scenario: 工具被提交给模型

- **WHEN** 系统向模型发起决策请求
- **THEN** 请求中包含全部已注册工具的名称、描述与参数 Schema

#### Scenario: 工具缺少必需元数据

- **WHEN** 注册一个缺少名称、描述或参数 Schema 的工具
- **THEN** 系统拒绝注册并给出明确错误

### Requirement: 工具注册与查找

系统 SHALL 提供工具注册机制，允许在启动时集中注册工具；运行期系统 SHALL 能按名称查找到已注册工具并取得其执行入口。

#### Scenario: 按名称查找已注册工具

- **WHEN** 模型请求调用名称为 `calculator` 的工具
- **THEN** 系统在注册表中找到该工具并取得其执行入口

#### Scenario: 查找未注册的工具

- **WHEN** 模型请求调用一个未注册的工具名称
- **THEN** 系统不执行任何工具
- **AND** 回填内容中列出当前全部可用工具的名称，使模型可据此纠正

### Requirement: 语言模型基于 Schema 自主决策调用

系统 MUST NOT 在运行时硬编码「哪类问题该调用哪个工具」的判断；是否调用、调用哪个工具、传什么参数 SHALL 全部由模型依据工具的名称、描述与参数 Schema 决定。

#### Scenario: 模型选择工具

- **WHEN** 用户提问涉及天气
- **THEN** 由模型判断是否调用天气工具
- **AND** 系统不预设「天气问题 → 天气工具」这类映射关系

### Requirement: 工具调用参数校验

系统 SHALL 在执行工具前按其参数 Schema 校验模型给出的参数；校验失败时 MUST 返回可读错误而非直接崩溃。

#### Scenario: 参数类型不符

- **WHEN** 模型给出的参数类型与 Schema 声明不符
- **THEN** 系统不执行该工具
- **AND** 将参数校验错误作为该次调用的结果回填

#### Scenario: 缺失必填参数

- **WHEN** 模型遗漏了 Schema 中标记为必填的参数
- **THEN** 系统不执行该工具
- **AND** 回填缺失字段的说明

### Requirement: 内置工具集

系统 SHALL 内置至少四个工具：`calculator`、`search`、`weather`、`todo`。

#### Scenario: calculator 执行数值运算

- **WHEN** 模型以表达式调用 `calculator`
- **THEN** 系统返回该表达式的计算结果
- **AND** 对非法表达式返回错误说明而非崩溃

#### Scenario: search 返回真实搜索结果

- **WHEN** 模型以查询词调用 `search`
- **THEN** 系统向已配置的搜索服务发起请求，返回结构化的搜索结果（标题、链接、摘要）
- **AND** 返回条数受配置的条数上限约束

#### Scenario: search 未配置服务凭据

- **WHEN** 在未配置搜索服务凭据的环境下调用 `search`
- **THEN** 系统返回一条说明服务未配置的可读结果
- **AND** 不崩溃，且其余工具与对话流程不受影响

#### Scenario: weather 返回真实天气信息

- **WHEN** 模型以城市名调用 `weather`
- **THEN** 系统先解析该城市对应的地理位置，再取得其当前天气
- **AND** 返回的是面向用户的天气文本描述，而非原始代码值

#### Scenario: weather 遇到无法解析的地名

- **WHEN** 模型以一个无法解析为地理位置的名称调用 `weather`
- **THEN** 系统返回可读的「未找到该地点」说明
- **AND** 不崩溃

#### Scenario: todo 写入与读取待办

- **WHEN** 模型调用 `todo` 新增一条待办
- **THEN** 该待办被写入当前会话的待办列表
- **WHEN** 模型调用 `todo` 查询待办
- **THEN** 系统返回当前会话内的全部待办
- **AND** 待办数据按会话隔离，不同会话互不可见

### Requirement: 工具执行结果回填格式

系统 SHALL 将工具执行结果以结构化文本回填到会话上下文，并携带与该次调用对应的标识，使模型能明确区分多个工具调用各自的结果归属。

#### Scenario: 结果与调用标识关联

- **WHEN** 一个工具执行完成
- **THEN** 回填内容中包含该次调用的唯一标识
- **AND** 包含该工具的文本化输出

### Requirement: 工具名称别名与未知工具兜底

系统 SHALL 在按名称查找工具时先对名称做归一化处理，并支持工具声明的别名；当名称无法匹配任何工具时，系统 MUST 回填包含可用工具清单的说明，使模型能自行纠正。

#### Scenario: 模型使用了变体写法

- **WHEN** 模型请求调用一个仅大小写或分隔符与规范名不同的名称
- **THEN** 系统能匹配到对应的工具并正常执行

#### Scenario: 模型使用了已声明的别名

- **WHEN** 模型请求调用某工具显式声明的别名
- **THEN** 系统能匹配到该工具并正常执行
- **AND** 该次别名命中被记录进调用 trace

#### Scenario: 名称完全不匹配

- **WHEN** 模型请求调用一个不存在且无法归一化匹配的名称
- **THEN** 系统不执行任何工具
- **AND** 回填内容中列出当前全部可用工具的名称

#### Scenario: 不做模糊匹配

- **WHEN** 模型请求调用的名称与某个已注册工具仅拼写相近，但不构成归一化或别名匹配
- **THEN** 系统按未知工具处理
- **AND** 不猜测模型意图去执行那个相近的工具

### Requirement: 外部服务结果的截断

当工具从外部服务取回的结果超出配置上限时，系统 MUST 在回填前截断，并在结果中标注发生了截断。

#### Scenario: 单条结果过长

- **WHEN** 外部服务返回的单条内容超出配置的单条上限
- **THEN** 该条内容被截断到上限长度
- **AND** 结果中标注该条已被截断

#### Scenario: 结果总量过长

- **WHEN** 工具输出的总量超出配置上限
- **THEN** 超出部分被丢弃
- **AND** 结果中说明总量已被截断

### Requirement: 外部服务调用的超时与失败处理

工具对外部服务的调用 SHALL 受单次执行超时约束；调用失败时 MUST 以可读错误作为工具结果回填，MUST NOT 使整轮处理失败。

#### Scenario: 外部服务超时

- **WHEN** 工具的外部调用超出配置的超时时间
- **THEN** 该次调用被中断
- **AND** 超时信息作为该工具的结果回填

#### Scenario: 外部服务返回限流或服务端错误

- **WHEN** 外部服务返回限流或服务端错误状态
- **THEN** 工具按有限次退避重试
- **AND** 重试仍失败时，错误作为工具结果回填

#### Scenario: 外部服务返回不可解析的响应

- **WHEN** 外部服务返回的响应无法按其预期结构解析
- **THEN** 工具返回可读的解析失败说明作为结果
- **AND** 循环继续，由模型决定后续动作

### Requirement: 外部内容的边界标记

系统 SHALL 以明确的分隔标记包裹来自外部服务的内容，并在系统提示中声明工具返回的内容属于待分析的数据而非指令。

#### Scenario: 外部内容被回填

- **WHEN** 工具把外部服务的内容回填到上下文
- **THEN** 该内容被包裹在明确的分隔标记内
- **AND** 标记中指明内容来源

#### Scenario: 系统提示声明数据边界

- **WHEN** 系统组装发给模型的请求
- **THEN** 系统提示中声明工具返回的内容是数据而非指令
