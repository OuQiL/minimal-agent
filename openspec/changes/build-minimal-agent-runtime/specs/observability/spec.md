## Purpose

定义 Agent 循环各阶段的可观测性与异常处理契约，使每一次工具调用可追溯、每一次失败可诊断，且任何单点失败都不会导致会话不可用。

## ADDED Requirements

### Requirement: 工具调用 trace

系统 SHALL 为每一次工具调用产生一条 trace 记录，至少包含：会话标识、工具名称、调用参数、执行结果或错误、开始与结束时间、耗时、执行状态。

#### Scenario: 成功调用的 trace

- **WHEN** 一个工具执行成功
- **THEN** 产生一条状态为成功的 trace 记录
- **AND** 记录中包含工具名称、参数、结果摘要与耗时

#### Scenario: 失败调用的 trace

- **WHEN** 一个工具执行失败或其参数校验不通过
- **THEN** 产生一条状态为失败的 trace 记录
- **AND** 记录中包含失败原因

#### Scenario: trace 可被查看

- **WHEN** 用户在同一会话中执行查看 trace 的命令
- **THEN** 系统按时间顺序输出该会话的工具调用记录

### Requirement: 重复工具调用的检测与告警

当模型在同一轮处理中以相同参数重复调用同一个工具，或通过别名命中某个工具时，系统 SHALL 在 trace 中记录并告警，以便发现模型行为异常与工具描述缺陷。

#### Scenario: 相同参数重复调用

- **WHEN** 模型在同一轮内以相同参数重复调用同一个工具
- **THEN** trace 中记录该次调用
- **AND** 标注其为重复调用并告警

#### Scenario: 别名命中告警

- **WHEN** 模型以某工具的别名而非规范名发起调用
- **THEN** trace 中记录该次调用
- **AND** 标注其命中了别名

#### Scenario: 检测不改变执行行为

- **WHEN** 检测到重复调用
- **THEN** 系统仍正常执行该工具并回填本次结果
- **AND** 不复用先前的结果作为本次结果

### Requirement: 执行日志

系统 SHALL 输出运行期执行日志，覆盖循环的各个阶段，包括接收输入、决策结果、工具执行与收敛判断；日志 MUST 可输出到终端，并可选写入文件。

#### Scenario: 循环阶段可追溯

- **WHEN** 一次用户输入触发完整循环
- **THEN** 日志中依次出现决策、工具执行与收敛等阶段的记录
- **AND** 日志内容足以还原该轮的处理路径

### Requirement: 模型请求失败的异常处理

当模型请求因网络、鉴权、限流或服务端错误而失败时，系统 MUST 捕获该错误、记录日志并向用户返回明确说明。对发生在**请求建立阶段**的可重试错误，系统 SHALL 执行有限次重试，MUST NOT 无限重试；对**已开始向用户输出响应之后**发生的中断，系统 MUST NOT 重试。

#### Scenario: 请求失败后有限重试

- **WHEN** 模型请求在建立阶段返回可重试错误
- **THEN** 系统按配置的次数进行有限重试
- **AND** 每次重试均记录日志

#### Scenario: 流式请求在建立阶段失败

- **WHEN** 流式请求在输出任何内容之前遇到可重试错误
- **THEN** 系统按配置的次数重试
- **AND** 重试成功后正常进入流式输出

#### Scenario: 已输出后的流中断

- **WHEN** 流式响应在已向用户输出部分内容之后中断
- **THEN** 系统不进行重试
- **AND** 保留已输出的部分，并向用户如实说明响应中断

#### Scenario: 重试耗尽

- **WHEN** 重试次数耗尽后仍然失败
- **THEN** 系统向用户返回明确错误说明
- **AND** 会话保持可用，用户可继续下一次输入

#### Scenario: 鉴权失败

- **WHEN** 模型请求因密钥无效或权限不足被拒绝
- **THEN** 系统返回指向配置项的错误提示
- **AND** 不进行无意义的重试

### Requirement: 工具执行失败的异常处理

当工具执行返回错误时，系统 MUST 将错误信息作为该次工具调用的结果回填给模型，使模型可自行决定改用其他工具或如实告知用户；系统 MUST NOT 因单个工具失败而终止整个循环。

#### Scenario: 工具执行返回错误

- **WHEN** 一个工具在执行中返回错误
- **THEN** 该错误被作为该次调用的结果回填
- **AND** 循环继续，由模型决定后续动作

#### Scenario: 工具内部崩溃

- **WHEN** 某工具执行过程中发生非预期崩溃
- **THEN** 系统拦截该崩溃并将其转换为错误结果
- **AND** 整个进程不退出

### Requirement: 模型输出格式异常的异常处理

当模型返回的内容无法按其预期结构解析出工具调用或最终答案时，系统 MUST 记录原始响应内容并返回明确说明，MUST NOT 静默丢弃。

#### Scenario: 无法解析的响应

- **WHEN** 模型响应无法解析出任何可用内容
- **THEN** 系统记录该原始响应
- **AND** 向用户返回明确说明，会话保持可用

### Requirement: 异常不中断会话

任何单次异常 MUST NOT 使会话进入不可用状态；异常处理完毕后，用户 SHALL 能在同一会话中继续输入。

#### Scenario: 异常后继续对话

- **WHEN** 某轮处理因异常终止
- **THEN** 用户在同一会话中的下一次输入能被正常处理
- **AND** 该会话此前已持久化的历史不因该异常而损坏
