## Purpose

定义每次模型请求的上下文组装规则、多轮状态记忆与超长上下文压缩契约，使 Agent 在多轮对话与追问场景下保持连贯，同时不突破模型的上下文窗口。

## ADDED Requirements

### Requirement: 上下文组装

系统 SHALL 为每次模型请求组装上下文，内容包括系统提示、工具声明与当前会话的相关历史消息。组装策略 MUST 明确哪些信息进入上下文、哪些仅落盘而不进入上下文。

#### Scenario: 纯对话追问

- **WHEN** 用户在一个纯对话会话中提出依赖前文的追问
- **THEN** 组装出的上下文包含此前轮次的用户消息与模型答复
- **AND** 模型能正确消解追问中的指代

#### Scenario: 带工具的追问

- **WHEN** 用户就上一轮工具调用的结果提出追问
- **THEN** 组装出的上下文包含此前的工具调用请求与其结果
- **AND** 模型无须重复调用同一工具即可答复

#### Scenario: 工具调用过程的取舍

- **WHEN** 系统组装上下文
- **THEN** 工具的执行结果进入上下文
- **AND** 模型的中间思考过程按其对后续推理的必要性决定是否进入上下文

### Requirement: 最大轮次限制

系统 SHALL 支持配置单轮用户输入触发的最大工具调用轮次，以及会话历史进入上下文的最大消息数；两项配置缺失时 MUST 具备安全默认值。

#### Scenario: 配置最大工具轮次

- **WHEN** 配置的最大工具轮次为 N
- **THEN** 单轮用户输入最多触发 N 次工具调用决策
- **AND** 超过 N 次时按上限保护收敛

#### Scenario: 历史消息数上限

- **WHEN** 会话历史消息数超过配置上限
- **THEN** 系统按压缩策略处理后才提交给模型

### Requirement: 多轮状态记忆

系统 SHALL 在同一会话的多轮对话之间保持状态，使后续输入能正确引用先前轮次中出现的实体，例如城市名、待办事项、前次计算结果。

#### Scenario: 跨轮引用实体

- **WHEN** 用户先询问某城市的天气，随后仅以「那明天呢」追问
- **THEN** 系统能从历史中解析出所指城市
- **AND** 模型据此前的城市完成追问答复

#### Scenario: 跨轮引用工具结果

- **WHEN** 用户先要求计算一个表达式，随后要求对该结果再运算
- **THEN** 上下文中包含先前的计算结果
- **AND** 模型可基于该结果继续运算

### Requirement: 上下文超长的基础压缩

当会话历史超出配置阈值时，系统 SHALL 执行基础压缩后再提交给模型；压缩 MUST 保留最近若干轮原文，且 MUST NOT 丢失会话身份与关键事实，例如当前会话标识与未完成待办。

#### Scenario: 超出阈值触发压缩

- **WHEN** 会话历史长度超过配置阈值
- **THEN** 系统对较早的消息执行压缩
- **AND** 最近若干轮消息以原文保留

#### Scenario: 压缩后仍能回答追问

- **WHEN** 在一次压缩之后，用户就压缩范围内的信息提出追问
- **THEN** 模型仍能依据保留下来的摘要信息作出合理答复
- **AND** 若信息确已被压缩丢弃，系统如实说明而非编造

#### Scenario: 压缩不破坏会话身份

- **WHEN** 系统执行压缩
- **THEN** 当前会话标识与其未完成待办不被丢失

### Requirement: 记忆召回时机与放置方式可说明

系统 SHALL 在项目文档中明确说明记忆的召回时机与其在上下文中的放置方式。

#### Scenario: 说明召回时机

- **WHEN** 阅读项目文档
- **THEN** 可明确得知历史消息在何时被读取、何时被写入、何时被压缩

#### Scenario: 说明放置方式

- **WHEN** 阅读项目文档
- **THEN** 可明确得知系统提示、工具声明、历史消息、工具结果与摘要各自在请求中的排列位置及其理由
